wbniv · proposed PR description

On mos6502, a function that updates byte and word values through a pointer across a call fails with ran out of registers during register allocation at -O1, -O2, -O3, -Os, and -Oz:

#include <stdint.h>
extern uint16_t ext(uint16_t, uint16_t);

__attribute__((noinline))
void stage(uint16_t *p, uint16_t k) {
    uint16_t a = (uint16_t)(p[0] + k);
    uint16_t b = (uint16_t)(p[1] ^ a);
    uint8_t c = (uint8_t)(((uint8_t *)p)[4] + (uint8_t)b);
    p[0] = (uint16_t)(ext(a, 13849u) + b);
    p[1] = (uint16_t)(b - (uint16_t)c);
    ((uint8_t *)p)[4] = (uint8_t)((a >> 8) ^ c);
}

clang --target=mos -mcpu=mos6502 -Os -c mixed-width-call.c

TwoAddressInstructionImpl::rescheduleKillAboveMI moves the argument copy $a = COPY %arg above a folded arithmetic instruction that also uses %arg. This makes physical $a live through the arithmetic until the call. The arithmetic's virtual operands belong to Ac, whose only register is $a; even spilling cannot provide a legal register for them.

The dependency check already rejects interference with physical operands. Extend it to reject the move when every unreserved register in a crossed virtual operand's class overlaps a live physical definition of the moved instruction. Check all crossed instructions, since an intervening operand can have the same constraint. Classes with another allocatable register still permit the move. Reserved registers are not counted as available, since the allocator never assigns them.

Every move this rejects would necessarily have failed allocation: the moved definition is live through each crossed instruction, and the crossed operand must occupy a member of its class there, so no assignment exists and spilling cannot create one. The check does not model physical registers that were already live across the crossed instruction before the move; that is the pass's existing blind spot, and this change only stops it from creating a new unallocatable operand by itself.

Add a MIR test covering the accumulator argument, an intervening constrained index, and a legal copy into $x with a GPR temporary that has other allocation choices, using both LiveVariables and LiveIntervals. Add an IR test for the mixed-width call through full code generation at -O1, -O2, and -O3.

Simulated upstream review

No blocking correctness finding identified for the reported failure. These are local review notes, not maintainer comments.

  • Frontend reachability: the standalone C reproducer fails on unmodified upstream MOS; the small MIR cases intentionally isolate the transformation.
  • Correctness: check the current instruction and every intervening operand; only live physical definitions matter. Alias checks cover overlapping physical registers.
  • Optimization: reject only when every member of a crossed operand’s class overlaps. The legal-X test keeps a hoist with remaining GPR choices.
  • Coverage improvement applied: add the LiveIntervals invocation alongside LiveVariables. Baseline ordering assertions fail and candidate assertions pass in both paths.
  • Final review: the exact patch and source hashes match the validated bundle. All 18 individual ordering checks give the expected result across the baseline, assertion-enabled candidate, and rescheduling-disabled control, using both liveness analyses. The legal-X check rejects disabling the optimization wholesale. No additional source or regression changes were needed.
  • Scope: this is a conservative overlap guard, not a complete pressure analysis. The complete X86, ARM, and AArch64 CodeGen suites pass with assertions enabled (11,459 tests, 23 expected failures, 0 failures). Other backends and compile-time benchmarks remain outside the available evidence. Physical registers already live across a crossed instruction before the move are not modelled; the description says so.
