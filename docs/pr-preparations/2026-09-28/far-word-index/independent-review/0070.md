## Correctness audit

Source references below are in `vendor/llvm-mos/llvm/lib/Target/MOS/` unless stated otherwise.

| Area | Assessment and relevant source |
| --- | --- |
| Entry and target features | The legalizer makes s16 load/store custom only with `hasAccum16()` (`MOSLegalizerInfo.cpp:428–433`). Plain s16 loads reach `legalizeLoadStore16` at `2527–2533`. The far native path requires the accumulator feature and a 32-bit pointer (`2443–2464`); absolute addressing is tried first. `AllowWord` repeats the accumulator check (`3317–3325`). `+mos-xy16` implies `+mos-a16` in `MOSFeatures.td:33–37`; it does not make the word pseudo consume Y16. Existing far-pointer/CPU feature assumptions are unchanged by this patch. |
| Policy and attributes | Default `speed` requires codegen optimization level at least `Default` and rejects `hasOptSize()` and `hasOptNone()` (`3317–3323`; patch lines `112–120`). `Function::hasOptSize()` includes `minsize` (`llvm/include/llvm/IR/Function.h:713–715`). `off` disables this new runtime word fold. Explicit `all` bypasses both size and optimization-level/`optnone` gates; the MIR test deliberately covers `all` with `optnone`. The option does not disable existing constant-displacement or absolute word selection. |
| Access type | `isPlainFarWordLoad` requires `G_LOAD`, an s16 result, and a precise two-byte memory size (`3243–3247`). It does not admit word stores or extending loads as native word operations. Atomic access rejection and exactly-one-MMO checks occur in the user walk before mutation (`3263–3268`). |
| All users and escapes | The walk accepts only matching-pointer non-atomic accesses and constant nonnegative pointer-add descendants, with bounded recursion/displacement (`3254–3299`). Unsupported uses, including a pointer stored as a value, PHIs, comparisons, calls, copies, and selected fallback pseudos, decline the group. A word sibling is admitted only under the same function policy as the current access. Already-selected fallbacks remain a conservative reason to decline. |
| Mixed visitation and bounds | The first access examined sees the surviving word sibling and sets `HasWord`. This forces the whole group to 255 even if that first access is a byte and XY16 is enabled (`3357–3370`; patch `137–149`). `MaxEnd` includes displacement plus memory size minus one (`3274–3282`). Thus an offset maximum of 254 plus a word's last byte is accepted; a byte sibling at displacement 2 makes the group exceed 255. When a successfully folded word disappears from the pointer's use list, the remaining byte users already satisfied the earlier group bound. When a word falls back, the target pseudo still using the pointer rejects later partial folding. |
| Calls and arithmetic | The existing call scan and `noCallBetween` gates remain in force (`3084–3124`, `3351–3365`). A group with multiple accesses is declined in a function that may call; a single access needs an accepted call-free path from its pointer add. The index is built from the computed `Off` register, then its proven nonnegative constant displacement is added (`3375–3381`). It does not reassociate narrow arithmetic into pointer arithmetic. The separate 0069 range proof remains a dependency; this review traced its use but is not a substitute for its independent review. |
| Memory operands, atomic and volatile behavior | The emitted pseudo receives the original single MMO (`3389–3393`), so its size, alignment, pointer info, volatility, alias metadata, and other MMO properties survive. Selection clones those references onto the actual native load (`MOSInstructionSelector.cpp:3411–3417`), while the imaginary-register transfer remains internal. The fold replaces the load at its current insertion point and retains one native two-byte access. No atomic operation enters the new runtime fold. Existing atomic fallback semantics were not changed or certified by this patch. |
| Native selection and banks | The emitted `G_LOAD16_FAR_INDIR_IDX` already exists (`MOSInstrGISel.td:319–324`). Selection pins the base to Imag32 and uses `LDIndirLongIdx16` (`MOSInstructionSelector.cpp:3395–3417`). Its operands are Imag32 and Yc, with `MLow = 1`, and it expands to `LDA_IndirectIndexedLong` (`MOSInstrLogical.td:771–775`). Thus this is M16/Y8 even under XY16. The unchanged hardware addressing path supplies the bank carry; retained boundary executions described below support that path. |

The tests in `far-native-word.ll` also establish the preexisting distinction between native word consumers and values lowered into separate bytes. In particular, `legalizeLoadStore16` may narrow an s16 load used only by unmerges (`2435–2453`). Merely putting an i16 load in an IR test does not guarantee that it exercises the new word fold.

## Nonblocking coverage gaps

### C1 — Low priority: directly check a native word whose first byte is 255

`far-word-policy.mir:35–67` reaches maximum starting offset 254 and checks acceptance. `word129` at `199–231` reaches starting offset 256, which the early `MaxOff > Limit` check already rejects. The mixed displacement-2 cases check a sibling's displacement. None directly isolates rejection of a native word starting at 255 with its final byte at 256.

A concrete valid shape is an s16 `G_LOAD` with a two-byte MMO at `G_PTR_ADD %base(p2), (G_ZEXT %index(s8))`, with `%index` unconstrained. The current implementation correctly declines its runtime word fold because `255 + 1 > 255`. A matching case with the index restricted to 254 should fold. A focused MIR pair would protect the documented final-byte policy independently of the early maximum-offset check. This is a coverage gap, not an observed compiler failure or a claim that the hardware cannot perform a word access with Y=255.

### C2 — Low priority: strengthen word-specific guard and operand checks

The new test checks word pseudo names but not their base/index operands, the retained MMO, byte sibling opcodes, or disappearance of runtime pointer arithmetic (`far-word-policy.mir:28–33`, `356–531`). It also has no direct native-word negative case for an atomic MMO, an escaping pointer, a call between pointer definition and load, or disabled `mos-a16`. Every RUN line enables A16 (`1–9`).

Existing `far-indir-indexed.ll:359–468` exercises escape/call/sibling guards mostly through byte operations or i16 values that are returned as bytes. The retained `bounds.c` pressure case exercises a permitted call before the pointer add, rather than rejection of a call between the add and its load. The shared code guards look correct, but small native-word MIR cases would keep those guarantees explicit. Operand captures and MMO checks in the mixed cases would additionally protect the intended transformation rather than only the selected opcode. No new tests were written or run in this review.
