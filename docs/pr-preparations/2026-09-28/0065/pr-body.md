# [MOS] Keep profitable near stores in byte registers

This change extends near-store profitability after the native-width support tracked by [#321](https://github.com/llvm-mos/llvm-mos/issues/321) and the absolute unit-increment rule. The prepared series targets `26d7c2c1eebf98ca194b92609ba4e7540bfc6ef6`; the final optimization patch depends on the first two prerequisite patches. Upstream main alone does not contain the native lowering path.

Recognize ABI byte pairs used by near stores and byte-returned unit arithmetic, including canonical decrement; indirect call results with zero-size frame teardown; and zero-extended ABI bytes or near byte loads. Absolute decrement and indirect increment can share byte stores. Indirect decrement retains a native word store while narrowing its arithmetic. Loaded destination pointers retain native lowering because the measured sequence is 17 bytes versus 22 for explicit byte stores in both native modes.

The rules retain atomic exclusions, memory operands and volatile ordering, same-block checks, native consumers, and barriers for calls, inline assembly, and nonzero outgoing call frames. The added LLVM IR and MIR checks cover profitable shapes and these boundaries, including literal `G_SUB` forms and an actual 24-byte call-frame teardown.

On the extracted assertions-enabled build, the original regression fails in both native modes before this patch and passes afterward; default mode passes on both. The full MOS CodeGen and MC suites pass 145 tests with one unsupported. Replaying 36 identical LLVM IR inputs gives 486 function comparisons: 72 smaller, 414 unchanged, none larger, saving 282 bytes in aggregate. Default-mode objects are byte-identical across the comparison. These results replay backend code generation; the larger historical frontend/LTO corpus remains separate dated evidence.

The runtime fixture returns the host checksum `0xFA36` in default, A16, and XY16 modes on both MAME and bsnes-jg. All fixture machine code is generated by the extracted backend; the existing local frontend, SNES linker/startup libraries, and emulator harness supply the remaining execution environment. The fixture is an ordinary object with LTO disabled; the existing linker still materializes SDK bitcode for `exit` and `__memset`. Published [NMI tally demo evidence](https://biohack.net/snes/nmitally/) supports the prerequisite native interrupt contract; the demo was not rebuilt in this validation.
