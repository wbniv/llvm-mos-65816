wbniv · proposed PR description

llc -filetype=null still runs the MOS assembly printer. Its initialization expects a MOSTargetStreamer to emit target directives, but the null output path had no MOS target-streamer registration and supplied LLVM's generic null streamer instead.

Register a MOS null target streamer that accepts the directives used during initialization and discards output. Override finalization because the base MOS streamer uses ELF-specific behavior. Add a regression that runs diagnostic null emission and ordinary object emission.

The preserved regression input crashes on the recorded baseline and passes with the patched downstream build. The focused MOS lit test passes in the llvm-mos-65816-dev container. The historical upstream candidate was not rebuilt with this patch, so the validation establishes the matching-input result for the preserved baseline and the patched downstream build only.

Simulated upstream review

No blocking correctness finding identified for the reported failure. These are local review notes, not maintainer comments.

  • Frontend reachability: the standalone C reproducer fails on unmodified upstream MOS; the small MIR cases intentionally isolate the transformation.
  • Correctness: check the current instruction and every intervening operand; only live physical definitions matter. Alias checks cover overlapping physical registers.
  • Optimization: reject only when every member of a crossed operand’s class overlaps. The legal-X test keeps a hoist with remaining GPR choices.
  • Coverage improvement applied: add the LiveIntervals invocation alongside LiveVariables. Baseline ordering assertions fail and candidate assertions pass in both paths.
  • Final review: the exact patch and source hashes match the validated bundle. All 18 individual ordering checks give the expected result across the baseline, assertion-enabled candidate, and rescheduling-disabled control, using both liveness analyses. The legal-X check rejects disabling the optimization wholesale. No additional source or regression changes were needed.
  • Scope: this is a conservative overlap guard, not a complete pressure analysis. The complete X86, ARM, and AArch64 CodeGen suites pass with assertions enabled (11,459 tests, 23 expected failures, 0 failures). Other backends and compile-time benchmarks remain outside the available evidence. Physical registers already live across a crossed instruction before the move are not modelled; the description says so.
