[MOS] Select bounded runtime [dp],Y indexing for far byte accesses

Fold an offset from a runtime far pointer into the 65816's `lda/sta [dp],y`, which adds Y to the full 24-bit address with carry into the bank. A constant displacement of 1-3 becomes an 8-bit Y constant. A runtime offset folds when its known-bits maximum plus the last accessed byte fits Y (8 bits, or 16 bits under +mos-xy16), every user of the pointer add is a non-atomic byte access or a constant non-negative displacement leading only to such accesses (so the 32-bit add disappears), the base is not an absolute address, no call can separate the add from its accesses, and a function with calls has only one such access. The offset keeps its own integer arithmetic; an 8-bit Y is preferred when the users fit it.

Both folds erase the access, which can leave the pointer add and any constant-offset adds on it with only debug uses. They call dropDeadFarAddressDebugUses (from the far-access commit) with the access's former pointer, so the remaining DBG_VALUEs of those adds no longer name erased registers, which the machine verifier rejects under -g. Here the dead adds can hang off a base that stays live (the runtime pointer, or the runtime add the window keeps), so the helper now salvages each DBG_VALUE whose address is that live base plus constant offsets: it becomes the base with DW_OP_plus_uconst (a subtraction for a negative offset) and DW_OP_stack_value. This is sound because MOS DWARF has a 4-byte address size, so the DWARF stack adds all 32 bits of the far pointer and keeps a carry into the bank byte. A location below a runtime offset (which would need a variadic DBG_VALUE_LIST), one whose tree starts at a folded global or constant, and indirect or list forms still get $noreg.

With a 16-bit Y, the index stays in an Imag16 pair until emission: LDIndirLongYIdx/STIndirLongYIdx are emitted as `ldy zp` directly followed by the access, so no spill code can insert a `sep #$10` that clears Y's high byte.

Default-mode effect: identical on every MOS CPU for the fixed input set except mosspc700, which crashes in MOS Late Optimizations before and after; fixed separately by #584. Only far byte accesses change.

Tests: far-indir-indexed.ll covers 16-bit reads through a runtime far pointer and a far array subscript; constant displacements 1 and 3 (and 0 and 4, which are not folded); runtime byte offsets for loads, stores and a blit, with 8-bit and 16-bit (+mos-xy16) Y, masked, sign-extended and 16-bit-wrapping offsets; and the declining cases: unbounded 32-bit offsets, absolute bases, escaping pointers, calls between the add and its accesses, multiple accesses in a function with calls, and a sibling access out of range. It checks assembly and object bytes ($a7/$b7/$97) in +mos-a16 and +mos-a16,+mos-xy16 modes, and the fused pseudos after instruction selection. far-index-fold-debug.ll checks a -g runtime-offset byte fold under -verify-machineinstrs: the dead pointer's DBG_VALUE becomes $noreg, the base pointer's location is kept, and the fold happens. far-fold-debug.ll adds -g displacement-window cases (a load at base + 1, a store at base + 3, and a runtime offset plus 1), compiled verifier-clean at O0 and O2, and checks after the legalizer that each is salvaged to its live base with DW_OP_plus_uconst 1 or 3.
