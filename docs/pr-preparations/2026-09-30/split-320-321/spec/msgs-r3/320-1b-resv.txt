[MOS] Reserve Imag32 quads that overlap reserved pairs

Reserve an RL quad whenever either of its RS pairs is reserved: the stack pointer (RS0), the scavenger slot, the frame pointer, or pairs outside the imaginary window.

LLVM counts a register unit as reserved only when its root register and all of its super-registers are reserved. The RL quads of the previous commit are new super-registers of the RS pairs, so without this the stack pointer's byte units were no longer reserved. A function that makes a call with stack arguments, such as any variadic call, then aborted in the register coalescer, where live-range computation found a use of $rs0 without a def. The reduced test stops with "Use of $rs0 does not have a corresponding definition on every path" and "LLVM ERROR: Use not jointly dominated by defs."; the unreduced variadic call (the record's input) stops with "Invalid global physical register". This happened in every MOS CPU mode, including default mos6502 code.

Default-mode effect: the fixed input set gives the same results as before the RL registers were added, on all 14 MOS CPUs, including the four inputs that the previous commit changed: one that compiled again compiles, and three return to their earlier results.

Tests: imag32-reserved-pairs.ll, reduced from a SNES demo with llvm-reduce, compiles a variadic call in mos6502 and mosw65816 with the verifier on. Its comment names both failure signatures.

Validate: `build/bin/llvm-lit -v llvm/test/CodeGen/MOS/imag32-reserved-pairs.ll`.
