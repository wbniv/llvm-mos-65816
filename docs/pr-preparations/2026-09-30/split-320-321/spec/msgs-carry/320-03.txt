[MOS] Route far memory intrinsics to the far runtime

A G_MEMSET, G_MEMCPY or G_MEMMOVE with any address-space-2 pointer operand that is not expanded inline now calls the far runtime. Near and direct-page pointer arguments are cast to far (bank $00 under the DBR=0 contract), so both pointers use the far-pointer ABI.

The length selects the entry, and no length is truncated. A length that provably fits 16 bits (a constant up to 65535, or known bits that clear bits 16 and above) calls __memset_far, __memcpy_far or __memmove_far with a 16-bit size_t length. Any other length, such as a constant above 65535 or the loop idiom's zext(n) * 2, calls __memset_far32, __memcpy_far32 or __memmove_far32 with a uint32_t length. A length wider than 32 bits is narrowed to 32, because no far object can exceed INT32_MAX bytes (LangRef, "Allocated objects"). The runtime must provide all six entries; memmove chooses its copy direction from the full addresses.

On a CPU without 65816 long addressing a far memory intrinsic is diagnosed with the same error as a far load or store, before inline expansion or a runtime call.

The generic memory libcall would pass the far pointer to the near runtime and drop the bank byte, silently accessing the wrong bank. A single 16-bit entry would silently truncate a longer length: 70000 would become 4464 and 65537 would become 1.

Default-mode effect: none for the fixed input set (assembly and objects identical in mos6502 and mosw65816); only calls with far pointer operands change, and on non-65816 CPUs those are now diagnosed.

Tests: far-memset.ll checks a far constant fill over the inline limit and a variable-length far fill calling __memset_far, and a near variable fill still calling __memset. far-memop-length.ll checks constant lengths 65535, 65536, 65537 and 70000, unbounded runtime i32 lengths and the loop idiom's scaled length (the 32-bit entries), and provably bounded runtime lengths (the 16-bit entries), in plain mosw65816, +mos-a16 and +mos-a16,+mos-xy16. far-access-non-65816.ll adds a far memset to the non-65816 diagnostic checks.

Validate: `build/bin/llvm-lit -v llvm/test/CodeGen/MOS/far-memset.ll llvm/test/CodeGen/MOS/far-memop-length.ll llvm/test/CodeGen/MOS/far-access-non-65816.ll`.
