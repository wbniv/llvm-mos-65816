# [MOS] Recover near-index no-wrap proofs after loop strength reduction

This change recovers unsigned no-wrap proofs for near byte addresses on the 65816. It follows the native-width support tracked by [#321](https://github.com/llvm-mos/llvm-mos/issues/321). The prepared series targets `06bc967d2668c7c11c4d6eb43a6aed1f99ad258b`, and this patch depends on the first patch's native-width and near-memory prerequisites. Upstream main alone has no bank-wrap guard for this pass to serve.

On the 65816, indexed addressing carries into the next data bank, so a near pointer addition can fold into `(zp),y` or `abs,x` only when its 16-bit sum cannot wrap. The prerequisite accepts `nuw`, `nusw` with a nonnegative offset, or a known-bits bound. Loop strength reduction rebuilds byte addresses without their original `inbounds` flags. Simple copy and fill loops then form every address with `clc`/`adc` instead of indexing.

Immediately after LSR, `MOSRecoverNearNoWrap` examines scalar address-space-0 GEPs with an `i8` element and a single pointer-width index. It adds `nuw` when ScalarEvolution shows that the result is at least the base. Either the address is a `nuw` recurrence starting at that base, or the unsigned comparison is proven directly. This shape has no scaling, truncation or intermediate sum, so its addition cannot wrap exactly when the result is at least the base. The facts come from ScalarEvolution as preserved across LSR, so they describe the original program. The pass adds only `nuw`, runs only for 65816 subtargets, and is inserted by ID. `-mos-recover-near-nowrap=false` disables it. The pass itself is named `mos-near-nowrap-recovery`, because `opt` accepts every legacy pass name as an option.

The tests cover a copy loop regaining `(zp),y` and a fixed buffer regaining `abs,x`, in default and XY16 modes. They check the recovered IR flag for both proof paths. Controls cover an unflagged loop, a pointer-increment recurrence, a wrapping constant base, the stock 6502 exclusion, the disabled switch and `opt` startup.

On the extracted assertions-enabled build, both new tests fail with the prerequisite alone and pass with this patch; the second checks, in assertion builds, which proof recovered each flag. The MOS CodeGen and MC suites pass 145 tests, with one unsupported.

A frozen-IR replay compiled 412 C programs, in default, A16 and XY16 modes, with machine verification and the driver's `-disable-spill-hoist`. Across 1,045 paired configurations, 499 got smaller and 39 got larger, saving 69,616 bytes in total. The 39 larger configurations add 2,453 bytes; the largest are +575 and +543 bytes. There the recovered proof lets the legalizer fold each access independently, and the folds cost more register traffic than the shared computed address they replace. The legalizer has no cost model for that choice. With recovery disabled, every configuration reproduces the prerequisite's code.

The replay exposed one configuration that fails verification only with recovery enabled. It is a latent defect in the prerequisite's X-preservation pass: `preserveX` pushes the status register as defined after a call clobbered its flags. The fix belongs to that code, not to this patch.

The extracted backend compiled 65 corpus programs whose code changed, plus two near-address fixtures, in all three modes, and ran them on MAME and bsnes-jg. All 394 core checks match the host or manifest oracle. The fixtures include a bank-wrap witness that must read bank `$7E` rather than carry into `$7F`. The existing frontend, linker and SNES startup libraries provide the rest of the execution environment. Four builds fail to compile with the prerequisite alone as well, on known undefined-register copies after virtual-register rewriting.

The published [SNES LZSS gallery](https://biohack.net/snes/lzss-gallery/) is the demo in which the lost proofs were found; its near-address fixtures and 62-work gallery passed on the downstream compiler with this pass. The published ROM was not rebuilt with the extracted series.
