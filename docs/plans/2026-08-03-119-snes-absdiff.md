# #119 — Motion-Detect Difference Field (`absdiff`)

**Status:** DONE + PUBLISHED 2026-08-03 — clean positive, no compiler defect found. Round 7 compiler-probe ROM.

## Question and shape

Does the MOS legalizer and selector correctly handle the absolute-difference idiom
`a > b ? a - b : b - a` after LLVM recognizes it, across u8, s16, and u32? The deterministic
kernel executes all three widths for 192 steps and folds every result into one 16-bit CRC.

The visual uses the same three kernels to turn two drifting source fields into three separated
motion-silhouette bands. Cyan edges and yellow differences come from the computed values; the
bottom strip tracks difference energy. Animation continues after the fixed-step gate publishes.

## Gates and result

- Host oracle: `0x3482`.
- A real non-LTO probe object passes `-verify-machineinstrs` and contains distinct u8, s16, and u32
  absolute-difference bodies with selected subtraction code.
- Default, `+mos-a16`, and `+mos-xy16` ROMs all return `0x3482` in bsnes-jg after 360 frames.
- Emulator screenshots were captured for all three target modes; the a16 frame became the paired
  site preview.

Result: clean positive. The operation is supported at all tested widths and no compiler change was
needed. Run with `dev/run.sh absdiff`.
