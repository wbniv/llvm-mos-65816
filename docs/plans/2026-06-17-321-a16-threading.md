## The problem, measured (not assumed)

Today every native s16 op is **self-contained**: `LDAImag16 → (clc/sec) OP Imag16 → STAImag16`. The value
lives in an `Imag16` zero-page pair *between* ops — the deliberate 1d-retry invariant that solved the
coalescer crash ("**no COPY ever bridges an `Ac16` vreg and an 8-bit vreg; the accumulator is entered/left
only via load/store**"). The cost: a dependent chain stores each intermediate and immediately reloads it.

`unsigned short f(){ unsigned short t=a+b; unsigned short u=t&c; r=u-d; }` at `+mos-a16 -Os` →

```
rep #32
lda b ; clc ; adc a ; sta __rc2 ; lda __rc2 ;   ← store-then-reload, SAME location
                      and c      ; sta __rc2 ; lda __rc2 ;   ← again
                      sec ; sbc d ; sta __rc2 ; lda __rc2 ; sta r
sep #32 ; rts
```

`.text.f` = **0x27 (39 B)**. Three redundant `sta __rc2; lda __rc2` round-trips (6 instrs, ~12 B) — the
value is already in `A16` and never leaves M=16 (one rep/sep bracket spans the whole sequence). Threaded:

```
rep #32 ; lda b ; clc ; adc a ; and c ; sec ; sbc d ; sta r ; sep #32 ; rts   ← ~27 B (−30%)
```

The MIR shows why it is safe to remove: each `STAImag16` result is **single-use**, read only by the next
`LDAImag16`, and `A16` is unchanged across the pair (post-RA both sides coalesce to `$rs1`/`$a16`):

```
%4:imag16 = STAImag16 %22:ac16      $rs1 = STAImag16 killed $a16
%18:ac16  = LDAImag16 %4:imag16      $a16 = LDAImag16 killed $rs1     ← lda is redundant; sta is dead
```

**Key reframing.** "A16-threading" need not start with RA-level `Ac16` residency (the *genuine hard core*
that crashed the 1d prototype — an 8-bit `LDImm` coalescing into `A16`'s sublo → `$a16 = LDImm`). The same
*outcome* — value threaded through `A16` across ops — falls out of **redundant store/reload elimination**,
which touches neither the coalescer nor `Ac16` liveness. We attack the win cheaply and safely first, and
treat RA-residency as a gated last resort for whatever the peephole provably cannot reach.

## Approach — three phases, increasing risk, each gated on measured remaining win

### Phase 0 — size the prize (measure first)

Across the kernels (`k_crc16/k_fxmul/k_prng/k_bits/k_satadd/k_isort`), the corpus, and a fuzz sample,
count the redundant `STAImag16 R; LDAImag16 R` pairs and the bytes they cost; record a per-shape table
(`+mos-a16 -Os` bytes). This sets the target and tells us how much Phase 1 alone is expected to recover
vs. what is left for Phases 2–3. Governing lesson #1: predicted codegen has been wrong here — build the
real shapes, diff the bytes.

### Phase 1 — redundant-reload elimination (coalescer-safe; expected to capture the bulk)

A targeted peephole: when `STAImag16 R` is immediately followed by `LDAImag16 R` into `A16` with **no
intervening `A16` def/clobber** and **R's def is single-use** (read only by this load), delete the
`LDAImag16` (`A16` already holds the value) and DCE the now-dead `STAImag16`. Net: the value threads
through `A16`.

**DESIGN DECISION (resolved during Phase-1 investigation): a POST-RA peephole, not pre-RA RAUW.**
A pre-RA SSA forward (RAUW the loaded `ac16` vreg with the stored one, erase both) is elegant *but* it
leaves an `ac16` value live **across** ops, so RA/the coalescer must manage it — which is exactly the
entanglement that crashed the 1d prototype (`$a16 = LDImm`). Post-RA the danger is gone: RA has already
chosen `$a16` for both sides, so the round-trip is literally `$rsN = STAImag16 $a16` then
`$a16 = LDAImag16 $rsN`, and deleting it *after* coalescing cannot reintroduce the crash. Confirmed
shapes: `-print-after=instruction-select` shows the single-use SSA pair
(`%4:imag16 = STAImag16 %22:ac16` / `%18:ac16 = LDAImag16 %4`); `-print-after=finalize-isel` shows the
post-RA physical pair (`renamable $rsN = STAImag16 killed $a16` / `renamable $a16 = LDAImag16 killed
$rsN`). The pseudos use `PseudoInstExpansion` (MC-lowered), so they survive as named MIs through
`MOSLateOptimization`. Generic store-to-load forwarding does not fire here because these carry load/store
memrefs to the `Imag16` home and no MOS pass forwards them — a focused peephole that knows `R` is a fresh
compiler temp sidesteps the alias conservatism.

- **Where:** `MOSLateOptimization.cpp` (post-RA, runs at `addPreSched2` after `ExpandPostRAPseudos`; it is
  already a late-peephole pass and is mandatory). Match `STAImag16`/`LDAImag16` in physical form.
- **Transform:** for adjacent `$rsN = STAImag16 $a16` then `$a16 = LDAImag16 $rsN`: erase the
  `LDAImag16` (the store didn't change `$a16`, so it already holds the value); if `$rsN` is dead after the
  pair (its only reader was that load), erase the `STAImag16` too. Clear any now-stale `kill $a16` left on
  the store's use so the MachineVerifier stays happy and `$a16` reads live into the next op.
- **Gate (conservative — a miss must only *miss a win*, never miscompile):** strict adjacency, same
  `Imag16` reg, no `$a16` def between (trivial when adjacent), `$rsN` not read again before its next def
  (for the store-erase). Bail otherwise. `Imag16` regs are compiler temps — never volatile.
- **Verify:** `dev/measure-a16-threading.sh` shows the round-trip counts drop to ~0 on the dependent
  chains; the `a16thread` micro-test collapses to the threaded form; a16 suite + corpus 7/7;
  **fuzz 50/50** (0 mismatch/crash/error); `-verify-machineinstrs` clean (this is also the coalescer-crash
  guard on `a16localx`); `0002` round-trips.

### Phase 1 retrospective — what's left (measured 2026-06-17; broad fuzz scan + targeted disasm)

A mode-aware scan of **300 fuzz-generated programs** (`a16_fuzz.py gen`, compiled `+mos-a16 -Os`),
classifying each 16-bit `lda __rcN` reload, plus targeted disasm of fold shapes:

- **Adjacent 16-bit round-trips: 0.** Phase 1 fully captured its target.
- **Fold-while-threaded: already optimal.** `t=a+b; u=t+0x0345; r=u^0x00FF` → `lda a; clc; adc b; clc;
  adc #837; eor #255; sta r` and `t=a+b; u=t+g; r=u-h` → `…adc g; sec; sbc h; sta r`. Both interior
  **immediates and near-abs globals fold directly into the threaded chain** — no `Imag16` materialization,
  one rep/sep bracket. The existing selection-time folds (immediate fold, mixed-operand abs fold) compose
  with the Phase-1 peephole for free, because they run at *selection* (before the round-trips existed) and
  Phase 1 only strips the inter-op round-trips post-RA. **So Phase 2's stated rationale is already done.**
- **Non-adjacent removable (relax-adjacency): ~40 / 300 (~0.13/program).** A `sta __rcN; <non-A-op…>;
  lda __rcN` where `A16` was never clobbered (e.g. `sta __rc2; sta gs0; lda __rc2`). Phase 1's strict
  adjacency skips these. Small. Caveat: the raw store→reload count is dominated by the **byte-assembly**
  non-pattern (`sta lo; stx hi; rep #32; lda` assembling a 16-bit value from two 8-bit halves — *not* a
  reload); the mode-aware filter removes it, which is why the honest number is ~40, not the ~1180 a naive
  scan reports.
- **"Genuine reloads" (A16 clobbered between): large but mostly NOT recoverable.** Heavily contaminated by
  the same byte-assembly non-pattern; the true 16-bit-spill-and-reload residue is bounded by the
  **single 65816 accumulator** — when a second 16-bit value needs `A`, the first *must* round-trip through
  `Imag16` (you cannot hold two 16-bit values in one register). This is Phase 3's domain, and the
  architecture caps its realizable gain well below the raw count.

**Revised disposition:** Phase 1 captured the realizable peephole win. **Phase 2 (fold-while-threaded) is
already covered — do not pursue it as a separate effort.** The only clean peephole-reachable remainder is
the ~40 non-adjacent cases (a low-risk "relax adjacency" tweak, modest). Phase 3 stays deferred (uncertain
gain capped by the single accumulator, plus the coalescer-crash risk).

### Phase 3 — RA-level `Ac16` residency (the genuine hard core; gated behind Phases 1–2 + a full fuzz sweep)

Let `Ac16` vregs live *across* MIR instructions and let the register allocator/spiller decide residency —
the general solution (handles reused intermediates, register-pressure tradeoffs, cross-block residency
that a local peephole/fusion cannot). This is exactly what crashed the 1d prototype, so:

- **The lever already exists.** `MOSRegisterInfo::shouldCoalesce` (`MOSRegisterInfo.cpp:669`) already
  selectively *forbids* coalescing for shift/rotate-`AImag8` and inc/dec-`GPR` patterns. Add a rule that
  **rejects coalescing an 8-bit class (`Anyi1`/`Anyi8`/`GPR`) into `Ac16`/`A16`** — precisely the
  `$a16 = LDImm` corruption. Keep the `A16 = B:A` aliasing (it is load-bearing for transient-`A16`
  soundness — 1d-retry §root-cause).
- Then relax the selector to leave the running `Ac16` vreg live across dependent ops (drop the
  `STAImag16`/`LDAImag16`) where profitable, and rely on the `Imag16` spill path (`STAImag16`/`LDAImag16`
  for `Ac16` already exists, F3/soft-stack-spill work) when RA must spill it.
- **Acceptance gate:** the exact prototype-crashing shape (`a16localx.c`) + the full fuzzer sweep
  (`fuzz 200+`) + corpus, all clean. This is the risk the Tier-1 corpus was built to absorb. **Only
  attempt if Phases 1–2 demonstrably leave significant wins on the table** (governing lesson #3: a blanket
  change that risks regressions to win a sub-case is wrong — but a measured, gated, corpus-proven general
  win is the whole point of step 5).

## Measurement methodology

- Compare native-`+mos-a16` **with vs. without** each phase, same C shape (toggle the phase), in
  **16-bit-ambient** context (not a leaf — the dependent chains above already hold M=0 across the whole
  body, the realistic case). Decide on **bytes** (`-Os`), cycles as tiebreaker; report both.
- Watch for a phase that *adds* a `rep`/`sep` by changing the schedule — threading should only ever remove
  round-trips within an existing M=16 region, never split one.

## Micro-test (the correctness gate)

`examples/65816/a16thread.c` + `dev/a16thread.sh`: dependent heterogeneous s16 chain
(`t=a+b; u=t&c; v=u-d; …`) + a reused-intermediate variant (forces Phase 3's domain) producing a
`corpus_result`, asserted host == default == `+mos-a16` on **MAME + bsnes-jg**, with a disasm gate
(no `sta __rcN; lda __rcN` round-trip; one rep/sep bracket). Add the shape to `tools/a16_fuzz.py`
coverage (dependent-op trees) so threading is differentially fuzzed.

## Risks

- **Phase 1 peephole unsound across a clobber** → miscompile. Mitigation: conservative adjacency +
  `A16`-unclobbered + single-use gate; the fuzzer + both-emulator differential is the guard; bail on doubt.
- **Phase 3 reintroduces the coalescer crash** → the documented hard core. Mitigation: it is *gated behind*
  the `shouldCoalesce` barrier and the full corpus/fuzz sweep; do not start it until Phases 1–2 are landed
  and measured, and only if the remaining win justifies the risk.
- **Blast radius:** all dependent native-s16 sequences (broad). Mitigation: quiet box, full fuzz sweep
  before/after each phase (CLAUDE.md correctness gate).
