## Goal: easy to understand, validate and accept

The user's criterion is an easy process for reviewers, not merely smaller patches.

- **Understand.**
  - Each commit carries one concept.
  - Each commit is small enough to read in one sitting: aim for roughly 600 lines of non-test code or less, and split further by operation class when a concept is larger.
  - Its message states the contract and why the 65816 needs it, in the order a reviewer needs.
  - A per-series reviewer map lists the commits in order: purpose, key hunks, tests, and a dependency diagram.
- **Validate.**
  - Every commit includes the focused tests that exercise it.
  - Every commit gives one command a reviewer can run.
  - Opt-in commits show that default codegen is unchanged. Their evidence is identical output for the existing MOS tests and a fixed IR corpus, before and after the commit, in `mos6502` and plain `mosw65816`.
  - A commit that changes default output says so and shows the difference.
- **Accept.**
  - The order allows incremental merging.
  - Changes upstream can take on their own go in separate PRs that do not wait for the feature series. Candidates are the generic VirtRegRewriter undefined-lane fix (0028), the MC address-width patches and the copy-cost repair, where each can stand without the rest.
  - The feature PR then states its dependencies explicitly.

## Invariants

- **Same end state.** On destination `06bc967d2668`, the #321 series must end at exactly the tree produced by the monolithic native patch. Likewise, the #320 series, applied after the two MC-width patches, must end at exactly the tree of the monolithic far patch. Every later patch (0063/0065, near-index recovery, far-word patches 5–14) then applies unchanged, and its existing validation still holds.
- **Each commit stands alone.** Every commit builds with assertions, and the MOS CodeGen/MC suites pass. Tests land in the commit whose code they exercise, and no commit depends on a later one. Default-mode (`mos6502` and plain `mosw65816`) codegen changes are isolated in named commits that say so.
- **Messages describe the current contract.** Commit messages follow AGENTS.md and the PR Markdown rules: the contract and its evidence, with no history narration.

## Proposed #321 commits (native widths)

1. **Model native registers and feature gates.** `+mos-a16`/`+mos-xy16` features, subtarget queries, A16/X16/Y16 registers and classes with their DWARF numbers, and register-bank membership. There is no codegen change yet.
2. **Add native-width instruction forms and printing.** TSFlags for M/X width, 16-bit instruction and pseudo definitions, and immediate-width printing and assembly-printer support, with MC-level tests.
3. **Insert REP/SEP from M/X width requirements.** `MOSInsertREPSEP`: cross-block M/X dataflow, transition placement, STZ fusion and X preservation, with its registration and MIR tests.
4. **Legalize and select native-width operations**, in several commits by operation class, because selection and legalization are over 2,000 lines together:
    - 4a: native loads and stores, and G_LOAD16/G_STORE16;
    - 4b: arithmetic and logic, with accumulator residency;
    - 4c: compares and branches;
    - 4d: extensions and truncations, with the byte-index guard and wide any-extension.

    Each carries its own `a16-*`/`anyext-*`/`zp-byte-index` tests.
5. **Require a no-wrap proof before folding near indexes on the 65816.** `canFoldNearIndex` and its three callers. This changes plain `mosw65816` codegen, and the commit message says so.
6. **Define native call, spill, frame and scavenger behavior.** Register-info spills and scavenging, copy lowering, frame changes outside interrupts, and late optimization.
7. **Preserve interrupted M/X state in interrupt handlers.** The prologue/epilogue width protocol, with `interrupt-width-65816.ll`.

## Proposed #320 commits (far data)

1. **Add the far address space and 32-bit pointer quads.** Data layout, address-space lowering, the `Imag32` class and zero-page allocation. This commit must first be reconciled with open upstream #594, which defines the same register family.
2. **Legalize far pointer values and memory operations,** with `far-phi.ll` and `far-addressing.ll`.
3. **Select far memory accesses and lower long addressing.**
4. **Route far memory intrinsics to the far runtime,** with `far-memset.ll`. The commit message states the 16-bit length domain.
5. **Select bounded runtime `[dp],Y` indexing,** with `far-indir-indexed.ll`.

The boundaries are a proposal. The implementer may merge or split commits to keep each one building and passing, and records every change to this list with its reason.
