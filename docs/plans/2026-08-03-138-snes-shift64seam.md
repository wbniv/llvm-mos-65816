## Question and shape

Can the target correctly lower data-dependent 64-bit left, logical-right, and arithmetic-right
shifts across 16- and 32-bit limb seams? The probe sweeps counts 0–63, with explicit coverage at
15/16/17 and 31/32/33, and folds all three results into a deterministic CRC over 96 steps.

Three synchronized texture bands visualize the tested shifts. A bright bottom marker identifies
the current seam, so incorrect cross-limb transfer or arithmetic sign fill visibly breaks the
pattern as well as changing the CRC.

## Gates and published result

- Host oracle: `0x2007`.
- LLVM IR contains variable `shl i64`, `lshr i64`, and `ashr i64` operations.
- The runnable form explicitly widens the data-dependent count to `uint64_t` before each shift.
- Host == default == a16 == xy16 == `0x2007` on MAME and bsnes-jg after 480 frames/ticks.

Run with `dev/run.sh shift64seam`.

## Finding retained from bring-up

At bring-up, the natural C form with a `uint8_t` shift count failed GlobalISel legalization at
`G_ANYEXT s8 -> s64`. The minimized source is retained in
`examples/65816/shift64seam-narrow.c`. Explicitly widening the count lets the complete shift
matrix run and proves the 64-bit shift operations themselves across every limb seam; it is a
workaround for the count-extension defect, not a backend fix.

## Fresh reproduction (2026-09-25, OpenAI Codex)

The retained minimal input passes all six optimization levels in default/a16/xy16.
A narrow-count runtime variant covering every count 0–63 agrees with the host
(`0x6A2B`) in default/a16/xy16 on MAME and a16 on bsnes-jg. The original failing
compiler was not recovered, so this is **not a proven fix**. Preserve the report
pending a discriminating baseline or identified causal change.
