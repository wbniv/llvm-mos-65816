48595d47	body	`lda mos16(240),x` assembles to `b5 f0` (zero page,X) and\n`lda mos24($123456)` to `a5 56` (zero page, address truncated to its low\nbyte). MOSOperand::isImmInRange's MOSMCExpr branch has two exits: the\nsymbolic one compares the modifier's fixup width against the candidate\noperand's width, the constant one never looks at `High` at all. Since\nMOSMCExpr::evaluateAsConstant has already masked the value to the\nmodifier's own width, `Value <= MaxValue` is true for every positive\nconstant, so the constant exit is effectively `return true` and any\nmodifier can fill any slot.\n\nThat makes MOSMCInstLower::wrapAbsoluteIdxBase a no-op: it wraps a\nzero-page-range indexed base in mos16() precisely so a later parse cannot\npick zero page,X, and the parser ignores it. `-c` and `-S`-then-assemble\ntherefore disagree on real code -- `bd f0 00` vs `b5 f0` for\n`((volatile char *)0xF0)[i]` -- and the two differ for every X >= $10,\nsince zero page,X wraps inside page zero while absolute,X carries.\n\nHoist the width relation so it guards both exits. The old\n`FixupKind == MOS::Imm16 && High < 0xFFFF` special case is the\nMaxValue == 0xFFFF instance of the general rule, so it is folded in\nrather than kept beside it (it never fired for the address-context\nspelling anyway: `mos16()` there parses to VK_ADDR16, a different fixup\nkind).\n\nThe change is strictly a narrowing -- it can only turn a `true` into a\n`false`, so a misclassification produces a `no matching instruction`\ndiagnostic, never a quieter encoding.
