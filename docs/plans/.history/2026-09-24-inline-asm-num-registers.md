84d87260	body	MOSTargetLowering has two inline-asm hooks that described the same operand\ndifferently. getNumRegistersForInlineAsm() is handed only a value type -- the\ngeneric interface passes no constraint -- so it answers "one register" for i16\non the strength of "r" mapping i16 to the 16-bit Imag16 class. But\ngetRegForInlineAsmConstraint() returned a single 8-bit GPR for "a"/"x"/"y" and\nan 8-bit class for "R"/"d" at any width. GlobalISel's InlineAsmLowering takes\nthe count from the first hook and the class from the second, so\n\n    define i16 @f() { %v = call i16 asm "lda #42", "=a"() ... }\n\nemitted the asm and then invented the high byte as `ldx #0`. Independent of\n+mos-a16, reproduces on mos6502, and older than 0041 -- 0041 made an analogous\nnarrowing explicit but this operand genuinely fits the one register the target\nasked for, so nothing downstream catches it. The input direction already failed\nloudly (buildAnyextOrCopy refuses to truncate a source), so the two directions\nof one constraint disagreed as well.\n\nContract chosen: reject.
