# #140 — Software Vectors (`brkcop`)

**Status:** implemented + verified 2026-08-04 — **clean positive**, `0xA34C`. Round 7, Cluster B.
**Plan item:** [Round 7 battery, Cluster B addendum #140](2026-08-03-round7-defect-hunting-demos.md).

## The platform defect this demo starts from

BRK and COP are the 65816's two **synchronous** (software) interrupts. In native mode each has its
own vector, distinct from IRQ. Before this change every SNES platform in the tree wired them like
this (`platforms/snes/link.ld:61`, and the identical line in `snes-far`, `snes-hirom`,
`snes-exhirom`, `snes-gallery`):

```
SHORT(0x0000) SHORT(irq)      /* $FFE4 COP,  $FFE6 BRK  */
```

Two separate faults:

- **COP → `$0000`.** A native-mode `cop` loaded PC from a slot holding the literal address zero and
  began executing bank‑0 `$0000` — the imaginary-register page — as code. Silent corruption, worse
  than a crash, and unreachable by any value gate because no program had ever executed a `cop`.
- **BRK → `irq`.** A `brk` landed in the shared hardware-IRQ stub with no way for a handler to tell
  the two apart.

Neither had ever fired: `nmi` is the only vector this platform has ever exercised. The fix is part
of the demo, exactly as the Cluster B addendum specifies.

## What was built

**Platform fix (all five SNES platforms).**

- `platforms/snes/crt0.c` — two new weak `rti` stubs, `brk:` and `cop:`, alongside the existing
  weak `irq:` / `nmi:`. crt0 is shared by every SNES platform, so one definition serves all five.
- `platforms/snes/link.ld`, `platforms/snes-far/link.ld`, `platforms/snes-hirom/link.ld`,
  `platforms/snes-exhirom/link.ld`, `platforms/snes-gallery/link.ld` — native `$FFE4` COP → `cop`
  and `$FFE6` BRK → `brk`; emulation-mode `$FFF4` COP → `cop` as well (it was also `$0000`).
  `$FFE8`/`$FFF8` ABORT stay `$0000`: the ABORT pin is not connected on the SNES, and widening the
  gate to cover it is a separate decision, recorded here rather than made silently.

**The probe.**

- `examples/65816/brkcop.h` — shared width-agnostic model: per-handler `brkcop_step` fold
  constants (`0x9E37` BRK / `0x7C15` COP, distinct so a BRK arriving at the COP handler — or at the
  old shared `irq` stub — changes the hash), the sentinel accumulator `brkcop_sent_mix`, and
  `brkcop_model()`.
- `tools/brkcop-sim.c` — host oracle, prints the greppable `gate_crc = 0x%04X`.
- `examples/snes/brkcop.c` — C `__attribute__((interrupt, noinline))` handlers named `brk` and
  `cop` overriding the weak crt0 stubs, plus four inline-asm trap sites: BRK and COP each fired
  once from a `rep #$30` (M=0/X=0) bracket and once from a `sep #$30` (M=1/X=1) bracket, 16 rounds
  = 32 BRK + 32 COP traps. Synchronous, so the counts are exact by construction; no armed/done
  handshake is needed, but all handler-shared state stays `volatile`.
- `dev/brkcop.sh` — the gate, modelled on the hardened `dev/nmitally.sh`.

### The signature-byte skip, and how it is asserted

Native BRK/COP push PB, **PC+2**, P — PC+2 because the opcode carries a one-byte *signature* the
CPU never interprets. RTI must therefore resume on the instruction **after** the signature byte.
Each trap site places a poison guard exactly there:

```
php
rep #$30
.byte $00,$42      ; brk #$42
lda #$5aa5         ; POISON GUARD (a9 a5 5a) — RTI must resume HERE
sta brkcop_sent16
plp
```

The value that reaches C is folded into the gate hash. Resuming one byte early executes the
signature byte as an opcode: `$42` is WDM, a two-byte reserved NOP, which swallows the following
`$A9` and desynchronises the stream into a direct-page `lda $5a`; `$5A` (the COP signature) is PHY,
which unbalances the stack. Either way the sentinel is wrong or the ROM diverges — the assertion is
that the ROM reproduces the host model's constants exactly.

### Assembler gap found along the way (not a codegen defect)

The MOS assembler has **no `cop` mnemonic at all**, and `brk` accepts no signature operand — both
`cop #$5a` and `brk #$42` are rejected as "invalid instruction". Both traps are therefore emitted
as explicit bytes (`.byte $02,$5a` / `.byte $00,$42`), which also pins the signature byte exactly.
`llvm-objdump --mcpu=mosw65816` likewise decodes `$02` as `<unknown>` and `$00` as a one-byte
`brk`, so its listing across a trap site is a linear-sweep artifact. This is an assembler/ISA-table
gap in stock llvm-mos, not a `+mos-a16` issue, and is out of scope for this demo; recorded here as
an upstream candidate.

## Result

**Clean positive.** No compiler finding. The interrupt envelope added for #123 (`MOSFrameLowering`,
`isISR && hasW65816`) is emitted on the software-entry path too, and the signature-byte skip is
correct in all three width modes.

- Host oracle `0xA34C` (32 BRK traps, 32 COP traps, sentinel accumulator `0x12C4`).
- `host == default == +mos-a16 == +mos-xy16 == 0xA34C` on bsnes-jg; a16 3× byte-deterministic.
- MAME leg SKIP-by-design (no SPC700 IPL locally) — the bsnes-jg leg is the load-insensitive oracle.

## Visual

No mockup bundle: the visible surface is a SNES framebuffer, proven by the real emulator captures
(`build/brkcop-{default,a16,xy16}-jg.png`) rather than by an HTML mockup, per the Round 7 per-demo
precedent (#123/#124/#128).

The field is split by a **vector seam** — two gold markers standing for the two now-distinct slots.
Above it a BRK lane, below it a COP lane, each carrying a travelling packet whose row and phase are
derived from that handler's *own* accumulated mix. One shared handler would move both packets in
lockstep; two separate vectors keep them independent. HUD: `B=0020 C=0020 CRC=A34C`.
