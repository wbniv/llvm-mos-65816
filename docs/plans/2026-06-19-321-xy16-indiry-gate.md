## Context

The `+mos-xy16` legalizer integration (16-bit index registers) is **already implemented** — `selectXY16`
has full direct + indexed handlers, and the legalizer has B1 (`allUsesAreXY16Compatible` → constrain a load
result to `Xc16`) and B2 (`Use16BitIdx` → 16-bit-index addressing). The TODO/handoff docs that still called
"legalizer integration" an open follow-on were **stale**. Of the two B2 sub-paths:

- **`abs,X16`** (`G_LOAD_ABS_IDX16` → `LDXImag16`+`LDAbsXIdx16`) was already gated by `xy16ops`.
- **`(zp),Y16`** (`G_LOAD_INDIR_IDX16` → `LDYImag16`+`LDIndirYIdx16`) was **fully wired but had NO test**
  (zero references in `dev/`/`examples/`; emitted at `MOSLegalizerInfo.cpp:2528`, selected at
  `MOSInstructionSelector.cpp:2751`).

An implemented-but-unexercised codegen path is exactly where bugs hide — the program-scope version of this
gap hid the `globals.c` crash and motivated `corpus-a16`. This adds the missing dedicated differential gate
for the `(zp),Y16` 16-bit-index path.

## What was done

- **`examples/65816/xy16indiry.c`** — a runtime pointer (`volatile unsigned char *volatile` → `Imag16`-resident
  base, the indirect `(zp)` form) + an unmasked `volatile unsigned short` byte offset of **`0x102` (>255)**.
  The unmasked u16 type (KnownBits can't prove ≤8 bits, not a `G_ZEXT` from ≤8) trips the B2 gate
  (`MOSLegalizerInfo.cpp:2526`); the `>255` value means a *wrongly-8-bit* `Y` would address byte `0x02` and
  read the wrong value, so the differential catches a `Y`-truncation miscompile (not just a byte coincidence).
  `g_buf[0x102..0x103] = {0x5A,0x7E}` → LE `0x7E5A`.
- **`dev/xy16indiry.sh`** — modeled on `dev/xy16ops.sh` (codegen gate) + `dev/a16indiry.sh` (disasm style):
  (1) verify-machineinstrs clean `+mos-xy16`; (2) MIR gate `G_LOAD_INDIR_IDX16` (legalizer) + `LDYImag16` +
  `LDIndirYIdx16` (selector); (3) disasm `lda (dp),Y` (B1), no `iny/dey` byte-walk; (4) build default +
  `+mos-a16` + `+mos-xy16`; (5) MAME differential `host == default == +mos-a16 == +mos-xy16 == 0x7E5A`;
  (6) bsnes-jg confirm `+mos-xy16`.
- **`dev/run.sh`** — `xy16indiry` help/targets line (dispatch is automatic).
