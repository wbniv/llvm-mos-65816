# #141 — Bank/Direct-Page Windows (`dpbank`)

**Status:** implemented + verified 2026-08-04 — **defect measured, envelope EXTENDED, gate green
`0x4D5F`.** Round 7, Cluster B addendum — the last battery item.
**Plan item:** [Round 7 battery, Cluster B addendum #141](2026-08-03-round7-defect-hunting-demos.md).

## Question

The D/DBR half of the 65816 interrupt-entry contract. A native-mode interrupt entry pushes
PBR/PC/P, forces PBR to 0 and sets I — but leaves **D** (direct-page base) and **DBR** (data bank)
exactly as the interrupted code had them. The #123 envelope re-establishes M/X width and saves
A/X/Y, but touches neither D nor DBR. Compiled code depends on both every few instructions: every
`__rc` imaginary-register access (including the soft-stack pointer `__rc0/1`) is **D-relative**,
and every absolute load/store of a C object is **DBR-relative**.

Nothing the compiler emits moves either register (verified in the Round 7 audit: no `pld`/`tcd`
outside crt0's boot sequence) — but user inline asm legally can, and #125 `asmisland` is the
in-tree precedent for opaque asm islands inside native-width C. An NMI landing inside a
`phd … pld` or `phb … plb` window today runs the C handler on a moved direct page and/or a wrong
data bank. Like #123, the outcome is a design decision either way:

- **extend** the envelope — save D/DBR, re-establish the C ABI state (D=0, DBR=0), restore; or
- **document** "interrupt-enabled code must not move D/DBR" as the platform contract and make
  this demo its loud gate.

## Demo shape (decides the question by measurement)

Main arms the #123-style NMI handshake (stop count 120), then runs `DPBANK_WINDOW_ITERS`
iterations that each open two inline-asm windows:

- **D window** — `phd; pea dpbank_decoy; pld`: the direct page is moved onto a 64-byte
  sentinel-filled decoy buffer. Every `__rc` access an unfixed handler makes lands in the decoy;
  the soft-stack pointer it loads from there is garbage, so stores can go anywhere.
- **B window** — `phb; pea $7f7f; plb; plb`: DBR moved to bank `$7F` (the *second* 64K of WRAM —
  deliberately not `$7E`, whose low 8K the bank-0 addresses mirror; `$7F` makes every absolute
  access in an unfixed handler target genuinely different memory).

**Rendezvous, as in #139:** each window spins *inside the asm* until the handler's tally echo
byte changes, so every window provably contains at least one NMI entry — the landing is
structural, not probabilistic, in all three width modes. The spins pin their own width
(`php; sep #$20 … plp`) and use addressing that stays valid inside the window: plain absolute in
the D window (DBR still 0), and raw-encoded 24-bit long addressing (`.byte $af/$cf` + address +
bank `$7e`) in the B window, which ignores DBR entirely. Both spins are release-only-by-handler,
and the C caller guards each entry with `nmi_armed && tally ≤ 110` so a disarmed handler cannot
strand a spin.

The handler is deliberately D- and DBR-hungry: 10 rounds of 32-bit rotate/xor/add (`__rc`-heavy,
soft-stack framed), volatile absolute stores (tally, echo, mix), and a frame-resident volatile
local (the #139 C0-check shape). The differential CRC folds: tally (120), mix, `hits_d` and
`hits_b` (each exactly `DPBANK_WINDOW_ITERS` — every window closed), and the decoy checksum
(sentinels untouched). Host oracle computes the same closed-form values.

## Measurement (phase A — pre-fix toolchain, no D/DBR handling)

Recorded before any compiler change; this is the evidence that decided extend-vs-document.
Host oracle: `gate_crc = 0x4D5F` (tally 120, hits 20/20, mix `0xCBB995B8`, decoy `0x23A0`).
A D-only comparison value was also computed: `0x4D55` is what the ROM would produce if the moved
D were *harmless* (hits_b = 0, everything else nominal).

Two legs on the unfixed toolchain (a16), via a temporary probe script:

```
== jg: full (expect 0x4D5F) ==
SMOKE: FAIL off=0x59 len=2 got=0x0000 want=0x4D5F
== jg: donly (expect 0x4D5F) ==
SMOKE: FAIL off=0x59 len=2 got=0x078D want=0x4D5F
```

- **Full ROM: HANG.** `corpus_result` still 0 after 400 frames — the first B window never
  releases. With DBR=$7F the handler's absolute stores (tally, echo, mix) land in bank $7F, the
  real echo byte never changes, and the rendezvous spin waits forever. Exactly the predicted
  failure, and the worst shape: silent, no crash, no wrong value to catch.
- **D-only variant: CORRUPTION.** Completes with `0x078D` — not `0x4D55`, so this is not merely
  "hits_b is 0": the handler ran its `__rc` traffic through the decoy (garbage in, mix garbage
  out) and trashed the sentinels while "restoring" them.

**Phase-A side finding (demo-design, kept in the source as a comment):** the compiler promotes
small globals to the **zero page**, which silently turns every "absolute" access to them into a
D-relative one. The first probe run rendezvoused *inside the decoy* — the handler's echo store
and the spin's read both went through the moved D to the same wrong place, hiding the defect.
The demo's addressing claims require the shared globals pinned to genuinely absolute WRAM
(`__attribute__((section(".bss.dpbank")))`); with that in place the predictions landed exactly.

## Decision

**Extend the envelope** — confirmed by the phase-A measurement (a hang and a silent corruption,
both reachable from legal user code). Rationale, same shape as #123:

- The compiler owns the `__attribute__((interrupt))` contract: a handler must be callable from
  any machine state mainline code can legally reach, and #125 established that moving D/DBR in an
  asm island *is* legal mainline state. Documenting a restriction would retroactively outlaw it.
- The failure mode is the worst kind: a garbage soft-stack pointer read through a moved D turns
  into wild stores — silent corruption anywhere in WRAM, not a crash at the fault site.
- Cost is small and amortized: prologue `phb, phd, pea $0000, pld, phk, plb` (+10 bytes,
  +24 cycles), epilogue `pld, plb` (+2 bytes, +9 cycles), against an ISR prologue that already
  spends ~5 scanlines saving `__rc` registers (#139 measurement). All width-independent
  instructions, so they sit outside the `rep/sep` bracket concerns entirely; `phk; plb`
  re-derives DBR=0 from the hardware-forced PBR=0, and `pea $0000; pld` sets D without touching
  any register.

New envelope (65816 ISRs only, `isISR && hasW65816`, both `MOSFrameLowering::emitPrologue` /
`emitEpilogue`):

```
rep #$30                        rep #$30
pha                             pld
phx                             plb
phy                             ply
phb          <- new             plx
phd          <- new             pla
pea $0000    <- new             rti
pld          <- new
phk          <- new
plb          <- new
sep #$30
```

`llvm/test/CodeGen/MOS/interrupt-width-65816.ll` extends to check the full sequence; the exact
head/tail gates in `dev/nmitally.sh`, `dev/irqgate.sh`, `dev/brkcop.sh` move to the new contract
in the same commit (they are the recorded contract, and this demo's gate joins them), and #123,
#139, #140 re-run green on the rebuilt toolchain.

**Patch carriage — one deliberate deviation.** `patches/llvm-mos/0002-321-accum16.patch` was
already dirty in the shared working tree with another agent's in-flight SBC carry-in change when
this work landed, and a regenerated 0002 verifiably absorbed their hunks (caught by diffing the
regen against the pre-regen file). Per the hot-tree rule the foreign-dirty 0002 was restored
untouched, and the envelope extension ships as the standalone incremental patch
**`patches/llvm-mos/0026-321-isr-d-dbr-envelope.patch`** (the 0017 precedent; round-trip
verified against the reconstructed pre-state). Fold it into the next clean 0002 regen and drop
the file. The rebuilt-toolchain gotcha also bit once more: `llc` is not in the distribution
install set, so the FileCheck run needed an explicit `cmake --build … --target llc` first — the
stale binary was still emitting the old envelope a minute after the toolchain "rebuild" claimed
success.
