## Context

`dev/run.sh corpus-a16` (landed `c998d7f`) is the standing differential gate that builds the SNES corpus
under `+mos-a16`/`+mos-xy16` and asserts host == default == `+mos-a16` == `+mos-xy16` on MAME + bsnes-jg
(`globals.c` XFAIL'd). Locally green; never wired into CI. The corpus-a16 plan flagged this as the follow-on
("Wiring `corpus-a16` into CI … sensible follow-on once green locally"). This closes that gap.

**Facts that shape the design** (from `.github/workflows/smoke.yml`, `dev/corpus-a16.sh`, `tools/a16_fuzz.py`):

- `corpus-a16` is a **third prerequisite combination**, not coverable by either existing job as-is:
  - It needs the **from-source patched toolchain** (`build/llvm-mos-install`) — the stock `/opt/llvm-mos`
    in the dev image has no `+mos-a16`. The engine resolves it via `MOS_TOOLCHAIN` (default
    `build/llvm-mos-install`; `a16_fuzz.py:43`). → like the **`xcheck`** job, **unlike `smoke`** (stock).
  - It runs the differential on **MAME**, so it needs the **SPC700 IPL secret** (`SNES_SPC700_ROM_B64`).
    → like the **`smoke`** job, **unlike `xcheck`** (which needs no secret).
  - It also runs **bsnes-jg** (full coverage), which `dev/run.sh xcheck` already builds into
    `build/jgxcheck`; `corpus-a16` auto-detects it and falls back to `--no-bsnes` if absent.
- The `xcheck` job already builds **everything corpus-a16 needs except the BIOS**: cached from-source
  toolchain → SDK (`MOS_TOOLCHAIN`) → bsnes-jg (`build/jgxcheck`). MAME is in the dev image (both jobs use
  it). The runner filesystem persists across steps, so a step appended after the bsnes cross-check sees all
  of it. → **Extend the `xcheck` job**; do not duplicate the ~30–90 min toolchain build in a new job.

## Approach (decided)

Append two steps to the existing **`xcheck`** job in `.github/workflows/smoke.yml` (the only file changed);
keep the workflow `workflow_dispatch`-only. The `smoke` job is untouched.

1. **Provide SNES SPC700 IPL (from secret)** — copy the `smoke` job's step verbatim (id `bios`, materializes
   `dev/roms/s_smp/spc700.rom` from `secrets.SNES_SPC700_ROM_B64`, sets `has_bios` output, `::warning::` +
   skip when absent). Forks/PRs without the secret aren't failed — the corpus-a16 step just skips.
2. **corpus-a16 — boot each corpus program under `+mos-a16` in MAME + bsnes-jg** — `if:
   steps.bios.outputs.has_bios == 'true'`, `env: MOS_TOOLCHAIN: /work/build/llvm-mos-install` (matches the
   SDK-build step), `run: dev/run.sh corpus-a16`. Placed **after** the bsnes-jg cross-check so `build/jgxcheck`
   is present → full MAME + bsnes coverage.

Update the file-header comment + the job comment to note the job now also runs the a16 corpus differential.

**Why extend `xcheck` and not add a third job:** a dedicated job would re-restore the same toolchain cache,
re-build the SDK, and re-build bsnes-jg — pure duplication for no isolation benefit (single private workflow,
no cross-job contention). Grouping by toolchain-type matches the house style (the `smoke` job already runs
both the hello-smoke and the full `corpus` in one job).
