## #578 — approve

The rediagnosis is right and the evidence chain is complete: `virtregrewriter` emits a correct
`$a = COPY $y` at the loop header; `MOSCopyOpt` forwards it away, making A live around the back
edge; the pass's final loop recomputes each block's live-ins **once, in post-order**, which
visits the latch before the header, so the header's new `$a` live-in never reaches the latch;
`mos-late-opt` then treats A as dead scratch when lowering the `CmpBrZero`. The forwarding loop
itself walks reaching definitions and predecessors directly (`findReachingDefs`, `isClobbered`),
not live-ins, so stale liveness cannot have affected any forwarding decision. Placing
`fullyRecomputeLiveIns` between forwarding and dead-copy cleanup is the minimal correct fix, and
excluding the entry block matches the existing loop's convention.

This answers mysterymath's objection directly: the defect is in a MOS-only post-RA pass, the
coalescer and greedy RA were doing the right thing, and no generic LLVM change is involved.
~~Say that last part explicitly in the body, since the upstream angle was his stated concern.~~
(Done: sentence added to the diagnosis paragraph of `578-body.md`.)

## #589 — approve

Matches the reviewer's direction (`isTerminator`, scan `terminators()`), and the invariant test
uses the verifier itself, which is the right oracle.

Why the terminator flag cannot pessimize codegen: `CmpZero` is created by `expandCmpBr` /
`expandGBR` in the first `postrapseudos` run and every instance is replaced by a real
instruction in `mos-late-opt`. In that window the only passes are `mos-scavenging`,
`finalize-isel` (post-RA custom inserters) and a second `postrapseudos`. `analyzeBranch` does
return "cannot analyze" for a block whose first terminator is a `CmpZero`, but its only
in-window caller is `emitCmpBrZeroMultiByte`, which runs on blocks ending in
`CmpBrZeroMultiByte`, a different conditional branch that never shares a block with a
`CmpZero`. Branch folding runs before the window; block placement, tail duplication and branch
relaxation run after it. So the flag is purely a verifier invariant with no layout effect.

Measurement (not in Codex's validation, added here): I applied `589-complete.patch` on the
578 review tree, rebuilt `llc`, and compiled IR from all 111 `examples/65816/*.c` (two variants
each, with and without the `+mos-a16` feature string; the upstream llc ignores the unknown
feature) at `-O2 -verify-machineinstrs` with and without the change. All 176 outputs that
compile are byte-identical, and the failure set is identical too (46 legalization failures on
fork-only far-pointer shapes plus a pre-existing upstream RA crash on `k_trig16x`, both present
without the change). `llc` rejects `-Os`, so this is `-O2` only. Tree and llc restored
afterwards.

The corrected test expectation is right: the reverse walk meets `CmpZero $a` first, the
intervening `CmpZero $x` clobbers NZ so it cannot fold, and lowering picks the dead X as a
one-byte `TAX` (NZ from A). `CmpZero $x` then folds into `T_A $x`. The final N is A's value,
matching the original last compare.
