    fix(examples): give every reachable idle loop a forward-progress-proof body (wai idiom)
    
    An empty `for (;;) {}` (or a body reduced to comments only, e.g. "stay alive
    while MAME settles") is removable under C11 forward-progress rules, letting
    main() fall through into a reset loop -- exactly the class of hazard the
    cartsize-canary fix (3e80748, 92c1b74) hardened against by re-storing a
    volatile. That commit flagged but did not fix the other 173 files sharing the
    same bare idiom, since the existing differential gates assert only WRAM state
    and are insensitive to a reset loop.
    
    Adopted the idiom already in production use in the two most recently
    hardened demos (snes-video-codec-bench.c, snes-video-reel.c):
    
        for (;;) __asm__ volatile("wai");
    
    `wai` is never DCE'd (inline asm), so the loop survives regardless of NMI
    being enabled -- these are all TERMINAL halts (nothing runs after them), so a
    CPU parked forever on `wai` with no interrupt source is exactly as correct as
    one parked forever re-storing a volatile; the differential gates only inspect
    memory contents, not continued execution.

    loops -- display_frame()/PPU writes every iteration, not removable) and
