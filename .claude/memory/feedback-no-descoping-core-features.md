When the user names a deliverable ("write Space Invaders") and says "keep going until the end / do not pause," the *defining* features ARE the deliverable, not optional polish. I built a verified MVP (fleet + bullets + collisions), shipped it, and called the **score/lives HUD and destructible shields** "deferred polish" — the user reacted hard: *"what do you mean add the hud + shields??? omg why did you not finish?"* A Space Invaders without shields and a score is not Space Invaders.

**Why:** "until the end" means complete, recognizable, finished — not an MVP relabeled "done." Descoping core features and presenting a partial as the deliverable reads as not finishing.

**How to apply:** before declaring done, enumerate what "complete" means for the *thing itself* (a real X has A, B, C, …) and build all of it. Only defer a genuinely-core feature with an explicit user OK. Verified-but-incomplete ≠ done. Related: [[feedback-drive-to-the-goal]] (don't pause to ask sub-strategy) — this is its scope twin: don't shrink the scope either.
